# E-Commerce Sales Analysis & Business Intelligence Dashboard

A portfolio-ready end-to-end analytics project for exploring synthetic e-commerce order-line data. It demonstrates data generation and quality controls, a reusable Pandas pipeline, an indexed SQLite analytical store, SQL business queries, exploratory chart generation, customer RFM segmentation, and a seven-section interactive Streamlit dashboard.

> **Data note:** The included data is generated for demonstration. It is not sourced from a real retailer and should not be represented as actual business performance.

## Business problem

Sales teams need a consistent view of revenue, profit, customer retention, product mix, discount effectiveness, and geographic performance. This project turns raw order-line CSV data into a cleaned, queryable dataset and an interactive BI experience where every visual responds to shared filters.

## Objectives

- Create realistic repeatable sample data (6,000 order lines before quality issues are injected).
- Normalize and validate the raw records, retain a clean CSV, and persist the facts in SQLite.
- Provide reusable SQL for core commercial KPIs and product, customer, shipping, and discount analysis.
- Generate reproducible EDA charts and RFM-based customer segments.
- Deliver seven dashboard views with date, category, sub-category, region, state, payment, and customer-segment filters.

## Technology

Python 3.10+, Pandas, NumPy, SQLite, Streamlit, Plotly, Matplotlib, and Seaborn.

## Dataset

The order-line grain includes Order ID, Order Date, Customer ID/Name, Gender, Age, Product ID/Name, Category, Sub-Category, Quantity, Unit Price, Discount, Sales, Profit, Payment Mode, City, State, Region, Shipping Mode, and Order Status. It also includes Ship Date, Delivery Date, Expected Delivery Days, Actual Delivery Days, and Is Late Delivery for fulfillment analysis. It spans 2022–2025 with seasonal demand, distinct product-category price profiles, consistent order/customer dimensions, multiple orders per customer, varying discount levels, and both positive and negative line profit. A small number of duplicate rows, missing customer names, and inconsistent payment-mode formatting are intentionally introduced to make cleaning observable.

## Data cleaning and preprocessing

`analysis/data_cleaning.py` generates the reproducible source dataset and applies these transformations:

1. Removes exact duplicate rows and records missing required identifiers/dates.
2. Parses order dates and coerces numeric fields; fills missing numeric values with conservative defaults.
3. Normalizes text fields and category/payment labels and constrains invalid quantities, ages, and discounts.
4. Reconciles Sales to `Quantity × Unit Price × (1 − Discount)`; preserves valid negative Profit values.
5. Adds profit margin, month, year, quarter, day, day of week, delivery timing, an on-time flag, and an IQR-based sales-outlier flag (outliers are flagged, not discarded).
6. Writes `data/raw_data.csv`, `data/cleaned_data.csv`, and an indexed SQLite star schema exposed through the analytical `sales` view.

## SQL analysis

`sql/analysis_queries.sql` contains 18 independently executable queries: revenue, profit, order/customer counts, AOV, best sellers, most profitable products, category mix, monthly revenue, year-over-year growth, regional results, purchase frequency, repeat customers, payment mode, discount bands, loss-making products, high-value customers, and shipping-status performance.

SQLite is used to keep the project local and reproducible. `sql/schema.sql` creates customer, product, order, and sales-fact tables with primary keys, foreign keys, checks, and indexes. The `sales` compatibility view presents a flat analytical shape; `analysis_queries.sql` queries this view. The dashboard also reads the view, making SQLite the shared source for dashboard and SQL analysis. `validate_project.py` executes each named query against the generated database and checks referential integrity.

## EDA and customer segmentation

`analysis/eda.py` writes charts for sales/profit distributions, category and sub-category revenue, regional sales, monthly and yearly revenue, discount/profit relationship, numeric correlations, customer demographics and segments, and shipping transit time into `outputs/charts/`. `analysis/customer_segmentation.py` computes Recency, Frequency, and Monetary metrics per customer and assigns interpretable RFM segments (Champions, Potential Loyalists, At Risk, New Customers, Hibernating, and Big Spenders).

## Dashboard

Run `streamlit run app.py` from this project directory.

The sidebar navigation provides:

1. **Executive Overview** — revenue/profit/order/customer/AOV/margin KPIs, monthly trend, category mix, regional performance, and YoY revenue.
2. **Sales Analysis** — daily/monthly/quarterly/yearly revenue, category and sub-category mix, and top/bottom products.
3. **Profitability Analysis** — profit, margins, category and product profitability, loss-making products, and discount relationship.
4. **Customer Analysis** — unique/repeat customers, average spend, RFM segments, age/gender profile, and high-value customer table.
5. **Product Analysis** — best sellers, profitability, revenue share, quantity, and full product comparison.
6. **Regional Analysis** — region and state performance, a US state choropleth, and city-level results.
7. **Shipping & Fulfillment** — delivered orders, on-time rate, transit-time KPIs, performance by shipping mode, and monthly on-time trends.
8. **Business Insights** — filter-aware insight statements and recommendations calculated from the selected data.

Global filters include date range, category, sub-category, region, state, payment mode, customer segment, and order status. Use **Reset filters** to clear selections and **Download filtered CSV** to export the current slice. KPI cards compare the selected window with the immediately preceding window of equal duration when prior-period data is available. Currency is displayed in USD. The executive page includes order-status mix. Fulfillment metrics use simulated ship/delivery dates and should be treated as demonstration data, not actual carrier SLA results.

## Install and run

```powershell
cd ecommerce-sales-analysis
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m analysis.data_cleaning
python -m analysis.eda
python -m unittest discover -s tests
python validate_project.py
streamlit run app.py
```

The data-generation step is deterministic and can be rerun to recreate the CSV and database. To regenerate only the EDA visualizations, run `python -m analysis.eda`.

## Validation

`python -m unittest discover -s tests` runs regression tests for data quality, order/customer consistency, delivery-time calculations, RFM/insights, SQL integrity, all dashboard pages, global filters, and empty-delivery behavior. `python validate_project.py` verifies the minimum row count, sales/profit-margin and delivery reconciliation, all 18 SQL queries, business insight generation, and chart creation.

## Key business insights

On the current reproducible sample (6,000 cleaned order lines), the dashboard reports **$543,905.68 sales**, **$81,648.55 profit**, **3,319 orders**, **1,003 customers**, **$163.88 AOV**, and a **15.0% weighted profit margin**. Example filter-aware findings include:

- Electronics is the leading revenue category ($148,408; 27.3% share), and West is the leading profit region ($23,615).
- Robot Vacuum has the lowest aggregate product profit (-$665).
- December 2024 is the top revenue month ($19,472).
- High-discount orders show a 4.3% margin versus 21.8% in the low-discount band.
- The repeat-customer rate is 86.8%; generated delivered orders have an 82.2% on-time rate and 4.1-day average transit time.

Values above are synthetic examples for the checked-in seed and will change when the generation seed or dashboard filters change. They should not be presented as real company performance.
